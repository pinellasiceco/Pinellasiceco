The Problem

A field sales operation with no intelligence on where to go next

The business runs on walk-in sales to restaurants and bars in Pinellas County, Florida. Without any existing CRM or prospect data, every sales day was guesswork — which locations to visit, which had compliance problems that made them likely to buy, which had ownership structures that allowed a decision to be made on-site.

The data to answer these questions existed publicly — Florida's DBPR health inspection portal logs every restaurant inspection, citation, and violation. Nobody had built a system to turn that into a real-time sales intelligence feed. That became the architecture challenge.

Before
No CRM. No prospect data. No way to prioritize which of 9,000+ Pinellas County food service businesses to approach or why. Sales cadence was entirely reactive.
After
A live intelligence platform — 9,658 prospects scored, segmented, and routed. Fresh high-priority leads delivered daily from automated inspection data. Full field workflow from prospecting to signed certificate.
System Architecture

From raw public data to a routed daily lead queue

The system ingests, scores, and routes inspection data through a fully automated pipeline — from public government records to a field-ready mobile app in hours.

What Was Built

Six purpose-built components, zero off-the-shelf CRM

🔍
DBPR Scraper & Data Pipeline

Python scraper pulls Florida health inspection records daily with automated retry logic, REDIRECT error handling, and 7-day retry windows for delayed publishing. Processes thousands of inspection records into a normalized prospect database with citation history, inspection timing, and violation narratives.

⚡
Lead Scoring & Classification Engine

Citation analysis algorithm classifies leads as Gold (confirmed contamination language in inspection narrative), Cited (any ice machine violation), or Cold. Scores weight recency, citation frequency, and violation type. Identified 686 high-conviction contamination prospects from 9,658 total records.

📱
Mobile-First Field PWA

Progressive Web App deployable via GitHub Actions CI. Field reps see a prioritized daily route, prospect inspection history, ATP test entry, and real-time route optimization. Built to function on a hotspotted iPad in a restaurant parking lot — not a desktop CRM that happens to be mobile-friendly.

📋
CleanScore Certification System

Automated documentation workflow generates a dated, scannable compliance certificate (with QR code verification) after each service visit. Certificate pulls from Supabase in real time. Designed to serve as the official service record for manufacturer warranty claims and DBPR health inspections.

🗺️
Geographic Intelligence Layer

7-year DBPR citation analysis mapped to geographic clusters across Pinellas County. Inspection timing prediction model estimates when each account is next due for a visit, enabling proactive outreach before inspections rather than reactive follow-up after citations.

🔗
HubSpot + Stripe Integration

Prospect data pushed to HubSpot via API for pipeline tracking and follow-up automation. Stripe Edge Function handles subscription checkout directly from the field app. End-to-end flow from first walk-in contact to recurring monthly subscription without leaving the mobile interface.

AI Collaboration

How Claude was used in the build

This project was built in active collaboration with Claude (Anthropic) as the primary development partner — not as a code-generation shortcut but as a technical co-architect who could hold context across the full system and reason through tradeoffs.

🤖 Claude's role in this build

System architecture: Designed the full pipeline architecture — data ingestion, scoring logic, database schema (Supabase), and CI/CD deployment via GitHub Actions — through iterative technical discussion rather than one-shot prompting.

Python pipeline development: Wrote and debugged the DBPR scraper, citation narrative parser, gold lead classifier, and export scripts — including diagnosing structural rendering changes in DBPR that were causing systematic REDIRECT failures across new records.

Data quality and edge case handling: Identified that n_insp (inspection count) was fiscal-year-scoped rather than lifetime, which was producing incorrect "recently opened" classifications. Designed the JSON fallback fix for gold lead recovery from narrative data gaps.

Front-end PWA build: Generated all HTML/CSS/JS for the field app with strict constraints enforced throughout (no apostrophes in JS strings, no addEventListener on innerHTML-injected elements, base64-embedded assets for self-contained reports).

Business model pressure-testing: Used Claude to model pricing scenarios, financing structures, and unit economics before committing to the $129/month retainer model — running real numbers against market comparables (Easy Ice, Crystal Ice) to confirm viability.

What this demonstrates for client work: The ability to use AI as a genuine development partner — not for boilerplate generation but for architectural reasoning, debugging, and technical decision-making across a complex, multi-component system built to production standards.
